# 新 Rust Vue 编译器设计：同时支持 Vue 2 / Vue 3

目标：

1. 同时支持 Vue 2、Vue 2.7、Vue 3。
2. 完整通过官方 compiler 测试用例。
3. 使用 Oxc 解析 template 内联 JS 表达式、事件语句、`v-for` 表达式、SFC `<script>` / `<script setup>`。
4. 提供完整、可扩展、可测试的 compiler 抽象，而不是只写一个 template-to-string 转换器。

## 官方兼容边界

必须以官方仓库测试为准，而不是 README 或自写 fixture。

Vue 3 官方测试入口：

- `vuejs/core/packages/compiler-core/__tests__`
- `vuejs/core/packages/compiler-dom/__tests__`
- `vuejs/core/packages/compiler-sfc/__tests__`
- 后续应纳入 `compiler-ssr` 及 runtime/e2e 中依赖 compiler 的测试

Vue 2 官方测试入口：

- `vuejs/vue/test/unit/modules/compiler`
- Vue 2 compiler 源码位于 `vuejs/vue/src/compiler`

关键事实：

- Vue 3 compiler-core 的 `baseCompile` 是 `parse -> transform -> generate` 结构，并暴露可插入的 node/directive transform。
- Vue 3 compiler-sfc 的 `compileTemplate` 会选择 DOM/SSR compiler，注入 asset URL、srcset、scopeId、source map、HMR 等选项。
- Vue 2 的 `createCompilerCreator(baseCompile)` 会把 base options、modules、directives、warn、error/tip、`compileToFunctions` 包起来。

因此设计必须保留两套官方语义，而不是强行把 Vue 2 / Vue 3 抹平成一套 AST。

## 总体架构

采用“共享基础设施 + 方言适配 + 后端目标”的结构：

```text
source
  -> SourceManager / SpanMap
  -> SFC parser
  -> Template tokenizer / CST
  -> Dialect parser: Vue2Ast 或 Vue3Ast
  -> JS parser: Oxc expression / statement / script AST
  -> Semantic HIR
  -> Dialect transforms
  -> Runtime MIR
  -> Codegen IR
  -> JS code / source map / diagnostics
```

核心原则：

- Vue 2 和 Vue 3 公共的是 HTML tokenization、source map、diagnostics、Oxc 集成、pass scheduler、code writer。
- Vue 2 和 Vue 3 不共享最终语义层：slot、model、static optimize、patch flag、block tree、filters、scoped slot、SSR 的语义差异太大。
- 测试兼容模式优先：为通过官方测试，必须支持 `ExactMode`，输出、错误、AST shape 尽量与官方一致。

## 核心抽象

### Dialect

```rust
pub trait VueDialect {
    type Ast;
    type Options;
    type TransformState;
    type CodegenOptions;
    type Output;

    fn parse_template(&self, input: &TemplateInput, options: &Self::Options) -> Self::Ast;
    fn transform(&self, ast: &mut Self::Ast, ctx: &mut TransformContext<Self>);
    fn generate(&self, ast: &Self::Ast, options: &Self::CodegenOptions) -> Self::Output;
}
```

实现：

- `Vue2Dialect`
- `Vue27Dialect`
- `Vue3Dialect`
- `Vue3CompatDialect`

### Transform Pass

```rust
pub trait TransformPass<N, Ctx> {
    fn enter(&mut self, node: &mut N, ctx: &mut Ctx) {}
    fn exit(&mut self, node: &mut N, ctx: &mut Ctx) {}
}
```

Vue 2 需要兼容 module hooks：

- `preTransformNode`
- `transformNode`
- `postTransformNode`
- `genData`

Vue 3 需要兼容：

- `NodeTransform`
- `DirectiveTransform`
- exit callbacks
- transform order

不要在第一版就设计过度通用的 plugin DSL。先把官方两套扩展点忠实映射到 Rust trait，再在上层提供统一 facade。

### AST / IR

分 4 层：

1. `CST`：尽量 lossless，保留标签、属性、原始文本、注释、source spans。
2. `Vue2Ast` / `Vue3Ast`：对齐官方测试可观察结构。
3. `HIR`：内部共享语义层，用于工具、lint、增量编译、IDE。
4. `MIR`：运行时代码生成层，区分 Vue 2 render、Vue 3 VDOM、Vue 3 SSR、未来 Vapor。

不要只保留 HIR。官方测试会检查 parse/codegen/diagnostic 的细节，`Vue2Ast` 和 `Vue3Ast` 必须作为一等结构存在。

## Oxc 集成设计

所有 JS 相关内容走 `vuec_js`，禁止在 transform 阶段用正则解析 JS。

需要支持的 parse mode：

```rust
pub enum JsParseMode {
    Expression,        // {{ foo + bar }}, :prop="expr"
    Statements,        // @click="foo(); bar()"
    Params,            // v-slot="{ item }", v-for aliases
    ForExpression,     // item in list / (item, i) in list
    ScriptModule,      // <script type=module>
    ScriptClassic,     // normal script
    TypeScript,
}
```

Oxc AST 生命周期策略：

- 每个 `CompilationUnit` 持有一个 Oxc allocator。
- Vue AST 不直接长期暴露 Oxc 引用；用 `JsAstId` 指向 `JsAstStore`。
- 每个 JS AST 节点记录 Vue source span 和 Oxc span 的双向映射。

```rust
pub struct JsAstStore<'a> {
    allocator: oxc_allocator::Allocator,
    expressions: Vec<oxc_ast::ast::Expression<'a>>,
    statements: Vec<oxc_ast::ast::Statement<'a>>,
    programs: Vec<oxc_ast::ast::Program<'a>>,
    span_map: JsVueSpanMap,
}
```

Vue 2 filters 是例外：`{{ msg | capitalize }}` 不是合法 JS。处理策略：

1. Vue 2 filter parser 先把 filter chain 切出来。
2. 每段表达式再交给 Oxc。
3. 转换为 Vue 2 官方语义：`_f("capitalize")(msg)`。

Vue 3 不支持 filters，compat build 另设 feature gate。

## Vue 2 编译链

Vue 2 编译必须保持经典流水线：

```text
parse(template) -> AST
  -> optimize(AST): mark static / staticRoot
  -> generate(AST): render + staticRenderFns
  -> compileToFunctions
```

重点模块：

- HTML parser：开始标签、结束标签、一元标签、可省略闭合标签、namespace。
- text parser：mustache、custom delimiters、filters。
- directives：`v-if`、`v-for`、`v-on`、`v-bind`、`v-model`、`v-html`、`v-text`、`v-pre`、`v-once`、`slot`、`slot-scope`、`scopedSlots`。
- optimizer：static / staticRoot / staticInFor。
- platform modules：class、style、model。
- warning/error：必须对齐 `outputSourceRange`。

Vue 2 的输出测试很多比较字符串，所以需要 `Vue2ExactEmitter`。内部可以有更漂亮的 codegen IR，但 parity 模式必须复刻官方输出风格。

Vue 3 compiler-core：

```text
baseParse
  -> getBaseTransformPreset
  -> transform
  -> generate
```

核心 transform 顺序必须可配置且默认对齐官方：

- `transformVBindShorthand`
- `transformOnce`
- `transformIf`
- `transformMemo`
- `transformFor`
- `transformExpression`
- `transformSlotOutlet`
- `transformElement`
- `trackSlotScopes`
- `transformText`
- directive transforms：`on`、`bind`、`model`

compiler-dom：

- DOM parser options
- HTML entity decode
- DOM-specific `v-model`
- `v-on` modifiers
- `v-show`
- Transition / built-in component handling

compiler-ssr：

- SSR-specific node/directive transforms
- string concat / buffer codegen
- `ssrRenderAttrs`
- slot SSR
- teleport/suspense/component SSR

compiler-sfc：

- `parse`: descriptor、blocks、custom blocks、line/column source map
- `compileScript`: normal script + setup script merge、macro analysis、binding metadata、TS type resolve
- `compileTemplate`: DOM/SSR compiler selection、asset URL/srcset transform、scopeId、slotted、HMR、source map merge
- `compileStyle`: scoped CSS、CSS vars、modules、preprocessors、source map
- `rewriteDefault`

## Diagnostic / Source Map

通过官方测试的关键不是只生成正确代码，还要错误位置一致。

设计：

- 全局 `SourceManager` 管理原始 `.vue`、template block、script block、style block 的 offset。
- 所有 AST 节点必须有 byte span。
- 诊断同时支持 byte offset、line/column、code frame。
- SFC template 编译时 source map 要支持二次映射：template block 内位置 -> 原 `.vue` 文件位置。

```rust
pub struct Span {
    file: FileId,
    start: u32,
    end: u32,
}

pub struct Diagnostic {
    code: ErrorCode,
    message: String,
    span: Option<Span>,
    severity: Severity,
}
```

## Conformance Harness

不要等实现完才跑官方测试。第一阶段就先做测试适配器。

### 官方测试同步

```text
xtask sync-official-tests \
  --vue2 https://github.com/vuejs/vue.git#<rev> \
  --vue3 https://github.com/vuejs/core.git#<rev>
```

把官方测试作为只读 fixture，记录 commit hash。每次升级 Vue 官方版本都单独开兼容 PR。

### 三层测试

1. `api parity`
   - 用 NAPI wrapper 暴露与官方 JS package 同名 API。
   - 在官方测试里 alias：
     - `@vue/compiler-core` -> `@vuec-rs/compiler-core`
     - `@vue/compiler-dom` -> `@vuec-rs/compiler-dom`
     - `@vue/compiler-sfc` -> `@vuec-rs/compiler-sfc`
     - Vue 2 compiler entry -> `@vuec-rs/compiler-vue2`

2. `differential`
   - 同一输入同时跑官方 JS compiler 和 Rust compiler。
   - 对比 AST、code、warnings、errors、source maps。
   - 字符串 code 先走 exact compare；必要时增加 AST-normalized compare 作为辅助诊断，不能替代官方 exact test。

3. `runtime`
   - 在 Node/jsdom 中执行生成 render。
   - Vue 2 和 Vue 3 分别挂载 runtime。
   - 验证 DOM、SSR string、hydration warning。

### 完成标准

“完全通过官方测试”只能这样定义：

- 固定 Vue 2 commit：compiler 单元测试 100% pass。
- 固定 Vue 3 commit：compiler-core、compiler-dom、compiler-sfc、compiler-ssr 测试 100% pass。
- 所有 skip 都必须是官方本来 skip，不能新增本项目 skip。
- CI 在 Linux/macOS/Windows + Node LTS 上通过。

## 实施路线

### Phase 0: Harness First

- 建立 workspace、NAPI wrapper、官方测试同步工具。
- 先让官方测试能跑起来，即使全部失败。
- 建立 snapshot/diff 输出。

### Phase 1: Source / HTML / Diagnostics

- 实现 source manager、line map、code frame。
- 实现 Vue-compatible HTML tokenizer。
- 跑 Vue 2 parser tests 和 Vue 3 parser tests 的最小子集。

### Phase 2: Vue 2 Compiler

- parser -> optimizer -> codegen。
- 先过 Vue 2 `parser.spec.ts`、`optimizer.spec.ts`、`codegen.spec.ts`。
- 再过 `compiler-options.spec.ts`、`codeframe.spec.ts`。

### Phase 3: Vue 3 compiler-core/dom

- baseParse、core transforms、codegen。
- DOM transforms、model/on/bind/show/html/text。
- 目标：`compiler-core/__tests__` 和 `compiler-dom/__tests__` 100%。

### Phase 4: SFC + Oxc Script

- SFC parse。
- Oxc 接管 `<script>` / `<script setup>` parsing、binding analysis、type-only import、props/emits model。
- `compileScript` tests 先跑通，再做 `compileTemplate` 与 source map。

### Phase 5: Style / SSR

- scoped CSS、CSS vars、CSS modules、preprocessor adapter。
- compiler-ssr pass。
- SSR runtime tests。

### Phase 6: Performance / Incremental

- arena allocation、string interning、incremental file cache。
- 并行 compile。
- benchmark 对齐官方 JS compiler、Vize、Verter、Fervid。

## 关键风险

1. Vue 2 filters 和 Vue 3 expression parsing 冲突：必须由 dialect feature gate 控制。
2. 官方测试会检查细节：AST shape、warning message、source range、code whitespace 都可能失败。
3. Oxc AST 生命周期复杂：必须用 `JsAstStore` 管理 allocator 生命周期。
4. SFC `compileScript` 是最大难点：TypeScript type resolve、import graph、宏行为、default export rewrite 都要精细复刻。
5. SSR 不应最后补丁式实现；Vue 3 `compileTemplate({ ssr: true })` 从一开始就要保留分支。

## 推荐设计取舍

不要从“统一 Vue 2 / Vue 3 AST”开始。正确顺序是：

1. 先做 lossless CST 和 SourceManager。
2. 再做 Vue2Ast / Vue3Ast 两套官方可观察 AST。
3. 最后抽出 HIR/MIR 给共享优化、工具链、IDE 使用。

不要先追求速度。通过官方测试之前，速度优化没有意义。

不要只做 render code 字符串生成。完整 compiler 抽象必须把 parser、transform、codegen、diagnostics、source map、plugin API、SFC/script/style/SSR 都作为一等模块。
