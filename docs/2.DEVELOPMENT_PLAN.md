# Rust Vue Compiler 开发计划

本文基于：

- `docs/0.RESEARCH.md`
- `docs/1.RUST_VUE_COMPILER_DESIGN.md`
- `docs/3.AST_HIR_MIR_DESIGN.md`（AST/HIR/MIR 的结构、投影和 lowering 规则以此为准）

目标是把“同时支持 Vue 2 / Vue 2.7 / Vue 3、使用 Oxc 处理 JS、完整通过官方 compiler 测试、具备完整编译器抽象”拆成可执行任务，并把 AST/HIR/MIR 结构、public projection、lowering 关系和验收产物全部固定为确定性清单。`docs/3.AST_HIR_MIR_DESIGN.md` 是 AST/HIR/MIR 的唯一结构约束，`Vue2Ast`、`Vue3Ast`、`HIR`、`Vue2Mir`、`Vue3DomMir`、`Vue3SsrMir`、`VaporMir` 都必须作为一等目标文档来验收。每个模块都必须能用简单信号判断是否完成。若与旧的泛化 IR 口径冲突，以 `docs/3.AST_HIR_MIR_DESIGN.md` 为准。

这里的 AST/HIR/MIR contract 不是抽象口号，而是直接验收 `NodeSpan`、`GeneratedReason`、`MissingSpanReason`、`LoweringMap`、`PublicProjection`、`TemplateSource.base_offset`、`JsAstStore`、`RuntimeHelper` 以及 target-split MIR 的可观察行为。

AST / HIR / MIR 的具体结构不再使用模糊的“泛化 IR”表述，而是直接采用 `docs/3.AST_HIR_MIR_DESIGN.md` 里的确定 schema：`Vue2Ast`、`Vue3Ast`、`HIR`、`Vue2Mir`、`Vue3DomMir`、`Vue3SsrMir`、`VaporMir` 都必须作为一等目标文档来验收。

## 完成判定总则

一个模块只有同时满足以下条件，才允许标记为完成：

- [x] 模块 API 已稳定到本阶段要求，公开类型有文档注释。
- [x] 模块单元测试通过。
- [x] 模块参与的官方兼容测试通过。
- [x] 模块参与的官方兼容测试必须标明覆盖来源：`rust-backed`、`shim-backed`、`mixed`。只有 `rust-backed` 或明确验证 Rust 输出的测试可以作为该模块完成证据。
- [ ] 诊断、source span、source map 行为有覆盖。
- [ ] 没有新增 `todo!()`、`unimplemented!()`、`panic!("TODO")` 进入主路径。
- [ ] CI 在 Windows、Linux、macOS 通过。

项目最终完成的判定：

## 确定性兼容验收标准

本节是兼容性验收的唯一口径。任何“兼容官方 Vue compiler”的完成声明，都必须同时通过本节定义的版本基线、API 导出、选项矩阵、输出契约和官方测试。

### 版本基线锁定

开发期可以临时跑 tag 或 branch，但合并到主分支的兼容报告只能读取 `compat/official-revisions.lock`。该 lock 文件必须是机器可读格式，并至少包含以下字段：

```text
vue2_6.repo
vue2_6.rev
vue2_6.npm.vue
vue2_6.npm.vue-template-compiler

vue2_7.repo
vue2_7.rev
vue2_7.npm.vue
vue2_7.npm.vue-template-compiler
vue2_7.exports["vue/compiler-sfc"]

vue3.repo
vue3.rev
vue3.npm.vue
vue3.npm.@vue/compiler-core
vue3.npm.@vue/compiler-dom
vue3.npm.@vue/compiler-ssr
vue3.npm.@vue/compiler-sfc
```

完成判定：

- [x] `cargo xtask verify-official-lock` 校验所有 `rev` 都是 40 位 commit SHA。
- [x] `cargo xtask verify-official-lock --require-vendor` 校验 npm 包版本与官方仓库 package manifest 一致。
- [x] `cargo xtask verify-official-lock` / `--require-vendor` 禁止 `latest`、`next`、`v2-latest`、`main`、`master`、semver range 作为验收输入，并要求 synced vendor checkout 的 `rev` 是 commit object 而不是 tag object。
- [x] conformance 报告头部记录 lock 文件 hash，报告无法脱离 lock 文件复现时判定失败。

| Vue 2.7 | `vue-template-compiler` | 同 Vue 2.6，并验证 2.7 行为不能回退成 2.6 |
| Vue 2.7 | `vue`（`vue/compiler-sfc`） | export manifest、SFC descriptor/result shape、`compileTemplate` / `compileScript` / `compileStyle` 入口行为 |
| Vue 3 | `@vue/compiler-core` | export manifest、helper enum、AST node type、error code 导出 |

### AST / HIR / MIR 结构验收

本节是 AST/HIR/MIR 的唯一结构口径。只有满足本节，才允许认为内部编译模型已经对齐新设计。
本节也是 `vuec_ast`、`vuec_pass`、`vuec_codegen`、`vuec_vue2`、`vuec_vue3_core`、`vuec_vue3_dom`、`vuec_vue3_ssr` 的共同验收标准。

必须满足：

- `AstDocument<K>` 节点必须包含 `NodeId`、`NodeSpan`、`parent`、`children`、`index_in_parent`。
- `NodeSpan` 必须显式区分 `Source`、`Generated`、`Missing`，并保留 `GeneratedReason` / `MissingSpanReason`；生成节点不能再用空值冒充正常源码节点。
- `LoweringMap` 必须显式记录 `ast_to_hir` 与 `hir_to_mir`，跨层关系不能藏进树边。
- `PublicProjection` 必须把 arena 结构还原成官方可比较的 public shape，不能补造内部已经丢失的信息；所有官方可观察字段都必须保留，尤其是 `loc`、`innerLoc`、`codegen_node`、`ssr_codegen_node` 这类 projection 字段。对于 Vue 3 directive，`arg` / `exp` / `modifiers` 的 `content`、`loc`、`isStatic`、`constType` 必须保持和官方 AST 一致，不能用统一 trim 或 synthetic fallback 掩盖差异。
- `Vue2Ast` 与 `Vue3Ast` 必须作为一等方言 AST 存在，它们的 public projection 必须能还原官方测试可比较的结构。
- `Vue2Ast` 的 projection 必须保留 `Vue2Root`、`Vue2Element`、`Vue2Text`、`Vue2ExpressionText`、`Vue2Comment` 的字段语义；`Vue3Ast` 的 projection 必须保留 `Vue3Root`、`Vue3Element`、`Vue3Prop`、`Vue3Directive`、`Vue3Text`、`Vue3Comment`、`Vue3Interpolation`、`Vue3CompoundExpression`、`Vue3If`、`Vue3IfBranch`、`Vue3For`、`Vue3TextCall`、`Vue3CodegenRef`、`Vue3SsrCodegenRef` 的字段语义，且 `Vue3Directive` 必须保留 `raw_name`、`arg`、`exp`、`modifiers`、`is_dynamic_arg` 的可观察差异。
- `Vue3Ast` 的 directive 语义必须保持在 `Element.props` 中，不能拆成独立 child node；`codegen_node` / `ssr_codegen_node` 也是 public projection 的可观察字段，directive arg 的原文内容不能被折叠或重写，且 dynamic arg 的 raw bracket span、`.prop` synthetic modifier、directive exp whitespace 都属于可观察差异。
- `HIR` 必须保留 `HirRoot`、`HirElement`、`HirComponent`、`HirText`、`HirInterpolation`、`HirIf`、`HirFor`、`HirSlotOutlet`、`HirSlotDecl`、`HirFragment` 的共享语义，不允许出现 `Call`、`Helper`、patch flag、hoist/cache、SSR push 或 codegen-only 节点。
- `HIR` 只能表达跨方言语义，不允许出现 runtime helper、patch flag、hoist/cache、SSR push 或 codegen-only 调用结构；所有方言 lowering 必须先落到 HIR，再进入对应 MIR。
- `MIR` 必须按目标拆分为 `Vue2Mir`、`Vue3DomMir`、`Vue3SsrMir`、`VaporMir`，codegen 只能消费对应目标的 MIR，不允许把多个目标收敛成单一通用枚举。
- `JsAstStore` 必须按 id 记录 JS 源、span、parse mode、source type，并提供 `JsExprId` / `JsStmtId` / `JsPatternId` / `JsProgramId` 的解析入口；JS program 不能退化成字符串拼接的旁路数据。
- `TemplateSource.base_offset` 必须把 SFC block 局部 offset 还原为原始 `.vue` 文件绝对 span。
- `RuntimeHelper` 必须是枚举，不允许 helper 名称退化回自由字符串。
- `DocumentPass` 遍历顺序必须稳定为 depth-first pre-order enter、post-order exit。
- `vuec_ast`、`vuec_pass`、`vuec_js` 的 snapshot / serializer 测试必须稳定，不允许依赖 `HashMap` 顺序。

完成判定：

- [x] `cargo test -p vuec_ast -p vuec_pass -p vuec_js` 通过。
- [x] `Vue2Ast` / `Vue3Ast` public projection 快照稳定且可重复比较，且 directive arg / exp / modifier 的 `content`、`loc`、`isStatic` 与官方 parse AST 一致。
- [x] `HIR` / `Vue2Mir` / `Vue3DomMir` / `Vue3SsrMir` / `VaporMir` 的 snapshot 和 target split 可重复比较。
- [x] `LoweringMap` 可追踪 AST -> HIR -> MIR 的映射。
- [x] `NodeSpan` 生成/缺失语义可在 snapshot 中区分，且 `GeneratedReason` / `MissingSpanReason` 可被快照比较。
- [x] `DocumentPass` 的 enter / exit 顺序和节点遍历顺序稳定可测。

## 每周开发节奏

建议每周只接受满足以下格式的增量：

- [ ] 本周目标只属于一个 P 阶段，除非是修 CI。
- [ ] 每个 PR 只推进一个模块或一个官方测试子套件。
- [ ] PR 描述必须包含“本 PR 完成判定”。
- [ ] PR 合并前必须更新本文对应 checklist。
- [ ] 每周生成一次 conformance 趋势报告。

## 不允许的完成声明

以下情况不得标记完成：

- [ ] 只通过自写 fixture，没有跑官方测试。
- [ ] 只生成看似正确的 render string，没有 runtime 执行验证。
- [ ] 只处理 ASCII/简单表达式，没有 Oxc parse 和 span 映射。
- [ ] source map 不可回溯到原 `.vue` 文件。
- [ ] 通过新增 skip 或修改官方断言来“通过测试”。
- [ ] panic / todo 仍存在主路径。
