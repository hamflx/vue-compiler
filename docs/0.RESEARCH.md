# Rust 写的 Vue.js 编译器深度测评

生成时间：2026-05-23  
范围：公开可访问 GitHub 仓库、crates.io、npm 包；重点核验源码是否以 Rust 实现 Vue template/SFC/JSX 的编译输出。

## 结论摘要

如果把“Vue.js 编译器”严格定义为“能把 `.vue` SFC 或 Vue template 编译成 render/runtime 代码”，当前公开可用且有实质源码的 Rust 项目主要是 7 个：`vize`、`verter`、`fervid`、`HerringtonDarkholme/vue-compiler`、`iris`/`iris-sfc`、`vuec-rs`、`lizidev/vue-compiler`。其中真正值得继续技术评估或试点的是前 3 个。

如果把 Vue JSX/TSX 也算作 Vue 编译器，还有 2 个 Rust JSX 专项编译器：`vuejs/vue-jsx-vapor` 和 `g-plane/swc-plugin-vue-jsx`。它们不替代 `.vue` SFC/template 编译器，但在 JSX/Vapor 或 SWC JSX 生态中是独立有效的 Rust 编译器。

推荐排序：

| 排名 | 项目 | 适用结论 |
| --- | --- | --- |
| 1 | `ubugeeei/vize` | 覆盖面最广，最像完整 Vue Rust toolchain；适合前瞻试点，不适合无验证直接替换生产编译链。 |
| 2 | `pikax/verter` | SFC 编译、类型、LSP、lint 深度最好；适合 IDE/类型分析和渐进式构建集成试点。 |
| 3 | `phoenix-ru/fervid` | 更聚焦替代 Vue SFC compiler；路线清晰但仍 alpha，SSR/边界特性还要验证。 |
| 4 | `vuejs/vue-jsx-vapor` | 官方组织下的 Vue JSX/Vapor Rust 编译器；只适合 JSX/TSX/Vapor 场景。 |
| 5 | `HerringtonDarkholme/vue-compiler` | 早期参考价值高，Rust Vue compiler 先驱；SFC/style/script/SSR 缺口明显。 |
| 6 | `g-plane/swc-plugin-vue-jsx` | SWC 版 Vue JSX 转换器，轻量可用；不是 SFC/template compiler。 |
| 7 | `itszzl-sudo/iris` / `iris-vue-sfc-compiler` | 面向自有 Iris/WebGPU/runtime 的 SFC 编译层；不适合作为官方 Vue 编译器替代。 |
| 8 | `tuchg/vuec-rs` | 目标正确但长期停滞，README 明确核心未完成。 |
| 9 | `lizidev/vue-compiler` | 有 parser/transform/codegen 雏形，但 SFC `parse` 仍 `todo!()`，成熟度最低。 |

## 纳入标准

纳入主评测的条件：

1. 主要实现语言是 Rust。
2. 目标对象是 Vue template、Vue SFC 或 Vue JSX/TSX。
3. 项目不只是解析 SFC 块，而是尝试产生 render function、JS runtime code、Vapor code、VDOM code、或类似编译输出。
4. 包装器、绑定层、Vite/Rspack 插件、linter/parser-only 项目不单独计入主类，除非同仓库内有实际编译器。

因此，`vue-oxc-parser`、`rust-vue-sfc`、`oak-vue`、`vue_oxlint_parser`、`vue_oxlint_jsx`、`vize_ex`、`unplugin-vue-fervid`、`fob-plugin-vue` 等被列为相邻项目，而不是 Vue 编译器主体。

## 1. Vize

仓库：`ubugeeei/vize`  
定位：Unofficial High-Performance Vue.js Toolchain in Rust。  
公开数据：707 stars，MIT，最后 push 2026-05-22；npm `@vizejs/native` 0.115.0，2026-05-22 更新。

关键证据：

- README 明确列出当前交付包，包括 `@vizejs/vite-plugin`、`@vizejs/native`、`@vizejs/wasm`、`@vizejs/unplugin`、`@vizejs/rspack-plugin` 等。
- `crates/vize_atelier_sfc/src/compile.rs` 暴露 `compile_sfc`。
- `crates/vize_atelier_dom/src/lib.rs` 暴露 `compile_template`。
- `crates/vize_atelier_ssr/src/lib.rs` 暴露 `compile_ssr`。
- `crates/vize_atelier_vapor/src/lib.rs` 暴露 `compile_vapor`。
- 文档 `docs/release/production-readiness.md` 明确说整个仓库还不是 stable production-ready toolchain。

能力评估：

Vize 是本次看到的最大、最完整的 Rust Vue 编译/工具链项目。本地统计约 901 个 Rust 文件、19.8 万行 Rust、2179 个测试或 fixture 相关文件。它不仅做 template/SFC 编译，还覆盖 SSR、Vapor、lint、LSP/IDE、CLI、native/wasm、Vite/Rspack/unplugin/Nuxt 等集成面。

优势：

- 覆盖面最完整：SFC、DOM template、SSR、Vapor、native、wasm、bundler plugin 都有。
- 活跃度最高：截至 2026-05-23，GitHub 和 npm 更新都非常新。
- 工程化意识强：有 production readiness、Vue parity matrix、release go/no-go 文档。

风险：

- 项目自己仍把整体定位为 alpha，不是完全生产就绪。
- 代码面很大，工具链横向扩张多，真实 Vue parity 需要按业务 fixture 跑完整回归。
- 若只需要“替换 `@vue/compiler-sfc`”，Vize 的范围可能过大，引入面也更宽。

适用建议：

优先作为前瞻试点或内部基准对象。若目标是研究 Rust Vue 编译器，Vize 应作为主参考对象；若目标是生产替换，需要以真实项目构建、SSR hydration、source map、HMR、scoped CSS、script setup 宏和第三方组件库作为门槛测试。

## 2. Verter

仓库：`pikax/verter`  
定位：full Vue compiler and toolchain built in Rust。  
公开数据：84 stars，MIT，最后 push 2026-05-21；crates.io `verter_core` 0.0.1-beta.1，npm `@verter/core` / `@verter/wasm` 0.0.1-alpha.3。

关键证据：

- README 明确说 `Verter is in alpha`。
- README 明确说它是 full Vue compiler/toolchain，能把 templates 编译为 optimized render functions，并生成 typed TSX 供 IDE analysis。
- README benchmark 声称平均比 Vue JS compiler 快 9.2x。
- `crates/verter_core/src/compile/mod.rs` 暴露 `pub fn compile`。
- `crates/verter_core/src/compile/types.rs` 有 compile target、template/render/TSX 输出类型。

能力评估：

Verter 的特点不是单纯追求 SFC 编译，而是把编译、类型分析、lint、LSP、component metadata、TS provider 集成为一个工具链。本地统计约 693 个 Rust 文件、44.7 万行 Rust、587 个测试或 fixture 文件。LOC 很高的一部分来自工具链、类型、fixtures、生成/快照内容，但仍说明实现面很宽。

优势：

- 类型和 IDE 方向明显强于其他项目，适合围绕 Volar/TS tooling 的替代或补充研究。
- 编译产物不止 render function，也包含 TSX/IDE virtual code。
- 有 native 和 wasm 包，便于 Node/browser 集成。
- README 给出明确 benchmark 数据和真实组件库测试叙述。

风险：

- alpha API，README 明确 API 可能变化。
- 它的 TSX 是为类型/IDE 服务，不能误解为 template compiler 唯一产物。
- 若只看生产构建替换，Verter 的 IDE/lint/analysis 大系统会增加引入复杂度。

适用建议：

适合做“Vue Rust 编译器 + 类型工具链”的研究基线。若团队痛点是 Vue template type-check、LSP、lint、component metadata，Verter 的价值高于单纯 template compiler。若只做 SFC build plugin，需要把 `@verter/native` 与现有 Vite/Rollup/Rspack 流程做兼容测试。

## 3. Fervid

仓库：`phoenix-ru/fervid`  
定位：All-in-One Vue compiler written in Rust。  
公开数据：427 stars，Apache-2.0，最后 push 2026-03-05；crates.io `fervid` 0.2.0；npm `@fervid/napi` 0.4.1。

关键证据：

- README 写明当前 alpha，目标是接近 Vue SFC compiler feature parity。
- README 显示 MVP 进度约 84%。
- `crates/fervid/src/lib.rs` 的 `compile` 注释写明 not production-ready yet。
- `crates/fervid/src/lib.rs` 暴露 `compile` 与 `compile_sync_naive`。
- `crates/fervid_napi/index.d.ts` 中 SSR 仍标注 TODO Support SSR。

能力评估：

Fervid 比 Vize/Verter 更聚焦 SFC compiler 替代。本地统计约 132 个 Rust 文件、2.94 万行 Rust、39 个测试或 fixture 文件。它有 parser、transform、codegen、CSS、NAPI、WASM 等模块，并且大量参考 Vue core/compiler-sfc 行为。

优势：

- 目标最清晰：替代 Vue SFC compiler，而不是构建一个过宽工具链。
- NAPI 包已经发布，Node 集成路径明确。
- README 对功能进度、MVP 和性能有明确陈述。

风险：

- 明确 not production-ready。
- SSR 不完整，部分 transform/codegen 仍有 `todo!()`。
- 测试/fixture 规模少于 Vize/Verter，需要用真实项目补验证。

适用建议：

如果目标是“找一个 Rust SFC compiler 做替换实验”，Fervid 是最聚焦的候选。但它需要重点验证：`script setup` 宏、`defineProps/defineEmits/defineModel`、scoped CSS、CSS vars、asset URL transform、HMR、source map、SSR、custom block、Vue compiler-sfc 边界 case。

## 4. vuejs/vue-jsx-vapor

仓库：`vuejs/vue-jsx-vapor`  
定位：Vapor Mode of Vue JSX。  
公开数据：297 stars，MIT，最后 push 2026-05-18；npm `@vue-jsx-vapor/compiler-rs` 3.2.14，2026-05-08 更新。

关键证据：

- `packages/vue-jsx-vapor/README.md` 写明 Vapor Mode of Vue JSX。
- 中文文档写明“Vue JSX 编译器，用 Rust 编写，并由 Oxc 驱动，支持生成 Virtual DOM 和 Vapor Mode”。
- `packages/compiler-rs/src/lib.rs` 暴露 `pub fn transform`。
- `packages/vue-jsx-vapor/src/core/index.ts` 从 `@vue-jsx-vapor/compiler-rs` 导入 `transform`。
- README 声称 Rust compiler powered by Oxc，VDOM 比 Babel 快 35x，Vapor 快 50x。

能力评估：

这是官方 `vuejs` 组织下的 Vue JSX/Vapor Rust 编译器。它不解析 `.vue` SFC，也不是 Vue template compiler 替代品；它编译 JSX/TSX 输入，支持 Vue JSX 指令/slot/component 语义，并可生成 VDOM 或 Vapor 相关输出。本地统计约 132 个 Rust 文件、3.09 万行 Rust、73 个测试或 fixture 文件。

优势：

- 官方组织项目，活跃度高。
- Oxc + Rust + NAPI/WASI/WASM 包路线清晰。
- Vapor 方向与 Vue 未来编译/runtime 方向相关。

风险：

- 只覆盖 JSX/TSX，不覆盖 `.vue` template/SFC。
- npm 包 `@vue-jsx-vapor/compiler-rs` 的 description 仍是 napi-rs 模板描述，包元数据不够精细。
- Vapor 本身生态仍需要结合 Vue Vapor 状态判断。

适用建议：

如果研究问题包含 Vue JSX 或 Vapor compiler，必须纳入；如果目标是替换 `@vue/compiler-sfc`，应单独列为“JSX 专项”，不应放入 SFC 主排行榜。

## 5. HerringtonDarkholme/vue-compiler

仓库：`HerringtonDarkholme/vue-compiler`  
定位：Vue's template compiler reimplemented in Rust。  
公开数据：1110 stars，MIT，最后 push 2026-05-19；crates.io `vue-compiler-core` 0.1.0 源自该项目作者。

关键证据：

- README 写明 Vue template compiler reimplemented in Rust。
- README 列出 NAPI、wasm npm package 的意图。
- `crates/wasm/src/lib.rs` 暴露 `baseCompile`。
- `crates/sfc/src/lib.rs` re-export `compile_script`、`compile_template`、`compile_style`。
- 但 `crates/sfc/src/template/mod.rs`、`style/mod.rs`、`setup_script.rs` 等有 `todo!()`。

能力评估：

这是 Rust Vue compiler 的早期标杆项目，stars 最高，核心 template parser/transform/codegen 很有参考价值。本地统计约 84 个 Rust 文件、1.53 万行 Rust、117 个测试或 fixture 文件。

优势：

- Vue compiler-core 移植参考价值高。
- 有 wasm/NAPI 思路，其他项目也引用了 `vue-compiler-core`。
- 代码规模适中，适合读实现。

风险：

- SFC 层不完整，compile_template/style/script setup 仍有 todo。
- SSR 路线仍不完整。
- 更像研究/参考实现，不像可直接替换生产 compiler-sfc 的工具链。

适用建议：

适合做源码学习和核心 compiler 设计参考，不适合作为生产候选。若要基于它继续开发，优先补 SFC、style、script setup、SSR 和 npm 发布链路。

## 6. g-plane/swc-plugin-vue-jsx

仓库：`g-plane/swc-plugin-vue-jsx`  
定位：SWC plugin for transforming Vue JSX。  
公开数据：98 stars，MIT，最后 push 2025-08-23；npm `swc-plugin-vue-jsx` 0.4.0，2025-03-13 更新。

关键证据：

- README 写明 mostly ported from official Babel plugin。
- `plugin/src/lib.rs` 使用 `#[plugin_transform]` 暴露 SWC transform。
- `visitor/src/lib.rs` 实现 JSX element/fragment/attrs/directive/children transform。
- fixtures 覆盖 `v-model`、`v-show`、`v-slots`、props/emits type resolving 等。

能力评估：

这是轻量 Vue JSX 转换器，不做 `.vue` SFC，也不做 Vue template compiler。它的价值在于用 SWC wasm plugin 替换 Babel Vue JSX plugin 的一部分能力。本地统计约 9 个 Rust 文件、3434 行 Rust、210 个测试或 fixture 文件。

优势：

- 目标窄，集成简单。
- fixtures 数量相对实现规模较多。
- 对已有 SWC 构建链路有直接价值。

风险：

- crates.io 上 `swc-plugin-vue-jsx` 0.1.0 的 repository 指向 `westhide/swc-plugin-vue-jsx`，该仓库已不可访问；npm 当前包指向 `g-plane/swc-plugin-vue-jsx`，元数据不一致。
- 不是 SFC/template compiler。
- Vue JSX 官方 Babel 插件功能 parity 需要逐项核对。

适用建议：

只在“Vue JSX + SWC”场景纳入。不要把它与 Vize/Verter/Fervid 放在同一类替代 `@vue/compiler-sfc` 的评测中。

## 7. Iris / iris-sfc

仓库：`itszzl-sudo/iris`、`itszzl-sudo/iris-vue-sfc-compiler`  
定位：Rust-powered Vue 3 runtime/framework with SFC/TS instant transpilation layer。  
公开数据：两个仓库 stars 都很少，MIT；`iris-sfc` crate 0.1.1，2026-04-30 更新。

关键证据：

- `crates/iris-sfc/src/lib.rs` 暴露 `compile`、`compile_from_string`、`parse_sfc`、`compile_template`。
- `crates/iris-sfc-wasm/src/lib.rs` 暴露 wasm `compileSfc`。
- `crates/iris-sfc/src/regex_patterns.rs` 用 regex 匹配 template/script/style、script setup 宏、style selector 等。
- `crates/iris-sfc-wasm/src/lib.rs` 还用 `source.find("<script")`、`source.find("<template")` 等方式抽取块。

能力评估：

Iris 确实有 Vue SFC 编译能力，但它的目标是服务 Iris 自有 runtime、WebGPU renderer、JetCrab/Boa runtime、buildless/dev server 等生态，而不是复刻或替换官方 Vue compiler-sfc。它的 SFC/block/macro 处理大量依赖 regex 和简化 parser，说明兼容性边界和可维护性风险较高。

优势：

- 有完整自有 runtime 场景，不只是孤立 compiler。
- WASM/CLI/dev server 方向完整。
- 对自有 DSL/runtime 可以快速迭代。

风险：

- 与官方 Vue runtime/compiler 兼容性不是核心目标。
- SFC 解析和宏处理的 regex-heavy 实现对 Vue 复杂语法不稳。
- 公开采用度极低，质量信号弱。
- `iris-vue-sfc-compiler` 看起来是 Iris 主仓库的变体/镜像/衍生，而非成熟独立 Vue compiler 产品。

适用建议：

如果研究的是“Rust 里自建 Vue-like runtime + SFC 编译”，可以纳入；如果目标是生产 Vue 应用的 compiler-sfc 替换，应排在后面。

## 深度差异分析

### 架构差异

Vize 走“大一统 Rust Vue toolchain”：compiler、SSR、Vapor、lint、LSP、bundler plugin、native/wasm 都在同一生态中。它的价值是面完整，代价是试点复杂。

Verter 走“compiler + type-aware IDE/tooling”：编译输出和 TSX virtual code/analysis/LSP 绑定紧密。它更像 Volar/ESLint/compiler 的 Rust 聚合替代，而不是单个 compiler-sfc 包。

Fervid 走“复刻/替代 Vue SFC compiler”：目标更窄，迁移路径理论上更直接，但功能缺口和 alpha 风险还在。

HerringtonDarkholme/vue-compiler 是“核心 compiler 移植参考”：核心概念价值大，但完整产品化不足。

Vue JSX 两个项目是独立赛道：`vue-jsx-vapor` 面向 Oxc + Vapor/VDOM JSX，`swc-plugin-vue-jsx` 面向 SWC JSX transform。

Iris 是“自有 runtime 的 SFC compiler”：不是官方 Vue compiler-sfc parity 路线。

### 兼容性差异

SFC/template 兼容性最值得看 Vize、Verter、Fervid。Vize 覆盖 SSR/Vapor，Verter 强在 TS/type/IDE，Fervid 强在 SFC compiler parity 目标。Herrington 和 lizidev 对 Vue compiler-core 的结构复刻有学习价值，但 SFC 层缺失明显。

对 `script setup`、`defineProps`、`defineEmits`、`defineModel`、withDefaults、type-only props/emits、top-level await、CSS vars、scoped style、asset URL transform、custom block、source map、HMR、SSR 的兼容性，任何项目都不应只看 README。必须拿真实 `.vue` fixture 跑对比。

### 性能证据差异

Verter README 给出了最清晰的公开 benchmark 表，平均 9.2x。Fervid README 给出进度和性能片段，但需要复现。`vue-jsx-vapor` README 声称 JSX VDOM 35x、Vapor 50x 快于 Babel。Vize 更强调完整 release/readiness 与多包 smoke gates，性能应结合其 benches 复现。

这里没有把 README 性能数字视为最终结论，因为不同项目 benchmark 输入、目标输出、是否包含 SFC parse/script/style、是否含 source map、是否生产优化不一致。公平 benchmark 应统一：

- 输入：同一批 Vue SFC，覆盖小模板、表单、slot-heavy、v-for/v-if-heavy、Element Plus/Naive UI/Vuetify 风格组件。
- 输出：client render、SSR render、Vapor、source map 分别跑。
- 指标：cold compile、warm compile、parallel compile、内存峰值、错误恢复、diagnostic quality。
- 对照：`@vue/compiler-sfc` 当前版本、Babel Vue JSX plugin、SWC plugin。

### 生态与落地差异

Vize 的 npm 包和 bundler 插件最全，适合构建链研究。Verter 的 IDE/LSP/native/wasm 生态适合开发体验研究。Fervid 的 NAPI 包适合作为 compiler-sfc drop-in 替代实验。`vue-jsx-vapor` 适合 Vapor/JSX 新路线。`swc-plugin-vue-jsx` 适合 SWC 构建链。其余项目不建议进入落地验证。

## 建议的评测方案

1. 第一轮：只测 Vize、Verter、Fervid、Vue JSX Vapor、SWC Vue JSX。
2. 第二轮：加入 HerringtonDarkholme/vue-compiler 作为 core parser/codegen 学习基线，不做生产候选。
3. 对 SFC compiler 候选统一跑 `@vue/compiler-sfc` parity fixture：
   - basic template、interpolation、v-if/v-for、slot、dynamic component、directive、v-model。
   - script setup macros、TS props/emits、defineModel、withDefaults、top-level await。
   - scoped CSS、CSS vars、preprocessor、asset URL。
   - SSR compile/hydration。
   - source maps 和 diagnostics。
4. 对 JSX compiler 候选单独跑：
   - 官方 `@vue/babel-plugin-jsx` fixtures。
   - Vue-specific directives：`v-model`、`v-show`、`v-slots`、custom directive。
   - TSX props/emits inference。
   - VDOM/Vapor 输出分别验证。
5. 生产试点顺序：
   - 先用 Vize/Verter/Fervid 对一个内部非核心 Vue app 做 read-only build 对比。
   - 再跑第三方组件库 fixture。
   - 最后才考虑替换构建链。

## 最终判断

当前没有一个 Rust Vue SFC/template 编译器可以在不做项目级回归的情况下直接宣称“可无风险替换官方 `@vue/compiler-sfc`”。但 Rust Vue compiler 生态已经明显分化：

- `vize` 是最完整、最值得持续跟踪的全栈候选。
- `verter` 是类型/IDE/编译一体化最强的候选。
- `fervid` 是最聚焦 compiler-sfc 替代的候选。
- `vuejs/vue-jsx-vapor` 是 JSX/Vapor 方向必须关注的官方相关 Rust 编译器。
- `HerringtonDarkholme/vue-compiler` 是重要参考实现，但不是生产替换候选。
- `swc-plugin-vue-jsx` 是轻量 SWC JSX 专项方案。
- `iris`、`vuec-rs`、`lizidev/vue-compiler` 目前更适合作为实验或历史记录。
