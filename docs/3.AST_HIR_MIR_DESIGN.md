# AST / HIR / MIR 确定性设计

本文是本仓库 `vuec_ast`、`vuec_html`、`vuec_js`、`vuec_pass`、`vuec_codegen`、`vuec_vue2`、`vuec_vue3_core`、`vuec_vue3_dom`、`vuec_vue3_ssr` 的 AST / HIR / MIR 目标设计。本文不描述候选方案，只描述本项目采用的确定设计。

## 设计原则

1. 官方兼容优先。Vue 2、Vue 2.7、Vue 3 的 public AST、错误位置、warning 顺序、source map、render 字符串都属于可观察行为。`Vue2Ast` 和 `Vue3Ast` 必须作为一等结构存在；共享的是内部载体与基础设施，不是同一个 AST schema。
2. 层次职责固定。CST 描述原文，AST 描述方言 parse/transform 视图，HIR 描述跨方言语义，MIR 描述目标运行时代码生成。helper、patch flag、hoist、cache、SSR push 不进入 HIR。
3. Source span 不丢失。所有节点使用 `vuec_source::Span` 指向原始 `.vue` 文件。由编译器生成的节点使用显式 `Generated` span，不使用 `None` 表示正常节点。
4. JS 表达式结构化。模板表达式、事件语句、`v-for`、slot 参数、SFC script 都由 `vuec_js::JsAstStore` 登记并解析。AST/HIR/MIR 中保存 `JsExprId` / `JsStmtId` / `JsPatternId`，不把裸 `String` 作为唯一语义来源。
5. Vue 2 / Vue 3 lowering 分离。`v-if` + `v-for` 优先级、filter、slot、model、static optimizer、patch flag、block tree、SSR 输出分别由方言 lowering 实现。共享 HIR 只接收 lowering 后的语义结果。
6. Arena 是唯一内部树结构。`AstDocument<K>` 继续作为内部树容器，所有 AST/HIR/MIR 文档都用 `NodeId` 索引。嵌套 `Box<Node>` 只用于 public projection，不用于内部主结构。
7. 快照输出确定。所有 map 类字段使用 `BTreeMap` / `BTreeSet`。源代码顺序使用 `Vec` 保存。snapshot serializer 不依赖 HashMap 顺序。
8. MIR 按目标拆分。`Vue2Mir`、`Vue3DomMir`、`Vue3SsrMir`、`VaporMir` 是不同 MIR 文档，不合并成一个泛化节点枚举。

## 与现有代码的对应

当前仓库已经有一组基础类型。本文对它们的设计角色如下。

| 现有位置 | 当前状态 | 设计角色 |
| --- | --- | --- |
| `vuec_source::Span` | 已有 `FileId + BytePos` | 全局共享源位置类型。 |
| `vuec_ast::AstDocument<K>` | 已有 `root`、`nodes`、`children` | 内部 arena 容器。 |
| `vuec_ast::Vue2NodeKind` | 极简占位 | 不是最终 Vue2 AST schema。 |
| `vuec_ast::Vue3NodeKind` | 极简占位 | 不是最终 Vue3 AST schema。 |
| `vuec_ast::HirNodeKind` | 含 `Call` / `Helper` | 与 HIR 职责不一致。 |
| `vuec_ast::MirNodeKind` | 类 AST 占位 | 与 MIR 职责不一致。 |
| `vuec_html::HtmlTokenizer` | 有 token start/end，无 attr span/quote | Template CST 的输入基础。 |
| `vuec_js::JsAstStore` | 已封装 Oxc allocator 和 parse 方法 | JS 表达式/语句/参数的登记式存储。 |
| `vuec_pass::TransformContext` | helpers 是 `RuntimeHelper` 枚举集合 | transform 共享上下文。 |
| `vuec_codegen::CodeWriter` | 已有 writer/source map builder | codegen 输出层。 |
| `vuec_vue2::Vue2Element` | 当前实现中的 Vue2 兼容模型 | Vue2 AST 字段集参考。 |
| `vuec_vue3_core::TemplateSource` | 无 block base offset | SFC template 的 source anchor。 |

## 基础 Arena

内部树统一使用以下结构：

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
pub struct NodeId(pub u32);

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct AstDocument<K> {
    pub root: NodeId,
    pub nodes: Vec<Node<K>>,
}

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct Node<K> {
    pub id: NodeId,
    pub kind: K,
    pub span: NodeSpan,
    pub parent: Option<NodeId>,
    pub children: Vec<NodeId>,
    pub index_in_parent: u32,
}

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum NodeSpan {
    Source(Span),
    Generated {
        origin: Option<Span>,
        reason: GeneratedReason,
    },
    Missing {
        reason: MissingSpanReason,
    },
}
```

规则：

- 正常解析节点必须使用 `NodeSpan::Source`。
- transform 生成节点必须使用 `NodeSpan::Generated`。
- `NodeSpan::Missing` 只用于错误恢复节点，并且必须带原因。
- `children` 是树边。跨层映射使用 `LoweringMap`，不塞进 `children`。

跨层映射固定为：

```rust
pub struct LoweringMap {
    pub ast_to_hir: Vec<(NodeId, NodeId)>,
    pub hir_to_mir: Vec<(NodeId, NodeId)>,
}
```

## Source Span 规则

`Span` 的 byte offset 永远指向 `SourceMap` 中完整原始文件，不指向临时 template substring。

`TemplateSource` 的 source anchor 由 `base_offset` 表达：

```rust
pub struct TemplateSource {
    pub filename: String,
    pub source: String,
    pub file_id: FileId,
    pub base_offset: usize,
}
```

规则：

- 普通字符串 template 编译时 `base_offset = 0`。
- SFC `<template>` 编译时 `base_offset = SfcBlockLocation.start`。
- `HtmlToken.start/end` 是相对 `TemplateSource.source` 的 offset。
- AST span 使用 `Span::new(file_id, base_offset + token.start, base_offset + token.end)`。

这条规则使 SFC `<template>` 的局部源码与原始 `.vue` 文件中的绝对 span 保持一致。

## JS 表达式 Store

id 类型定义在 `vuec_ast::ids`，`vuec_js` 使用这些 id：

```rust
pub struct JsExprId(pub u32);
pub struct JsStmtId(pub u32);
pub struct JsPatternId(pub u32);
pub struct JsProgramId(pub u32);
```

`vuec_js::JsAstStore` 是登记式 store：

```rust
pub struct JsAstStore {
    allocator: oxc_allocator::Allocator,
    expressions: Vec<JsEntry>,
    statements: Vec<JsEntry>,
    patterns: Vec<JsEntry>,
    programs: Vec<JsEntry>,
}

pub struct JsEntry {
    pub source: String,
    pub span: Span,
    pub mode: JsParseMode,
    pub source_type: JsSourceType,
}
```

规则：

- AST/HIR/MIR 中只保存 `JsExprId` / `JsStmtId` / `JsPatternId`。
- `JsAstStore` 保存 raw source、span、parse mode。
- Oxc AST 通过 `JsAstStore::parse_expr(id)`、`parse_stmt(id)`、`parse_pattern(id)` 按需解析。
- Vue2 filter 不是 JS 表达式，不能直接登记为 `JsExprId`。filter 先解析为 `Vue2FilterExpr`，其中 base 和参数再登记为 JS expression。

## RuntimeHelper

`RuntimeHelper` 是闭集枚举，表示 lowering / codegen 所需的 runtime helper 标识。它只表达“需要哪个 helper”，不保存字符串，也不承载拼接逻辑。

```rust
pub enum RuntimeHelper {
    Vue2CreateElement,
    Vue2CreateTextVNode,
    Vue2ToString,
    Vue2RenderList,
    Vue2ResolveFilter,
    Vue3OpenBlock,
    Vue3CreateElementVNode,
    Vue3CreateElementBlock,
    Vue3CreateCommentVNode,
    Vue3CreateTextVNode,
    Vue3Fragment,
    Vue3ToDisplayString,
    Vue3RenderList,
    Vue3RenderSlot,
    Vue3NormalizeClass,
}
```

规则：

- `TransformContext.helpers` 使用 `BTreeSet<RuntimeHelper>`。
- `Vue3Root.helpers` 记录 Vue3 transform 过程中需要的 helper。
- codegen 阶段把 `RuntimeHelper` 映射为目标 runtime 的导入名或调用名。
- helper 集合的 snapshot 顺序由枚举 `Ord` 和 `BTreeSet` 保证，不依赖插入顺序。

## CST

CST 是 lossless 模板树，来源是 `vuec_html::HtmlTokenizer`。

```rust
pub type Cst = AstDocument<CstNodeKind>;

pub enum CstNodeKind {
    Document,
    SfcBlock(CstSfcBlock),
    Element(CstElement),
    Attribute(CstAttribute),
    Text { raw: String },
    Comment { raw: String },
    Cdata { raw: String },
    Doctype { raw: String },
    Interpolation(CstInterpolation),
}

pub struct CstElement {
    pub raw_tag: String,
    pub self_closing: bool,
    pub open_span: Span,
    pub close_span: Option<Span>,
}

pub struct CstAttribute {
    pub raw_name: String,
    pub raw_value: Option<String>,
    pub quote: Option<QuoteKind>,
    pub name_span: Span,
    pub value_span: Option<Span>,
}

pub struct CstInterpolation {
    pub raw: String,
    pub open_span: Span,
    pub inner_span: Span,
    pub close_span: Span,
}
```

CST 规则：

- 保留 raw attr name，例如 `:class`、`.prop`、`@click.stop`。
- 保留 attr value quote。
- 保留 text/comment/cdata/doctype 原文。
- 只切分 `{{ }}` interpolation，不解析 JS。
- 不做 directive lowering。
- 不做 Vue2/Vue3 语义判断。

## Vue3Ast

`Vue3Ast` 是 Vue 3 compiler-core 方言 AST。它对齐 Vue3 parse/transform 可观察结构。

```rust

    If(Vue3If),
    IfBranch(Vue3IfBranch),
```

```rust
    pub cached: u32,

```

元素节点：

```rust
pub struct Vue3Element {
    pub tag: String,
    pub tag_type: Vue3ElementType,
    pub ns: HtmlNamespace,
    pub props: Vec<Vue3Prop>,
    pub self_closing: bool,
    pub codegen_node: Option<Vue3CodegenRef>,
    pub ssr_codegen_node: Option<Vue3SsrCodegenRef>,

    Element,

    Attribute(Vue3Attribute),

pub struct Vue3Directive {
    pub name: String,

    pub exp: Option<Vue3Expression>,

    pub is_dynamic_arg: bool,

```

Vue3Ast 规则：

- `Directive` 不是独立 child node。directive 永远在 `Vue3Element.props` 中。
- `codegen_node` 是 Vue3Ast 的可观察字段之一，因为 Vue3 compiler-core 的 transform 语义包含它。
- 最终 codegen 以 MIR 为边界，不以 `codegen_node` 直接作为 emitter 输入。
- `TemplateAttribute` 是 Vue3 属性投影的组成部分，不是独立的共享顶层类型。

```rust
    pub raw: String,
    pub base: JsExprId,
    pub filters: Vec<Vue2FilterCall>,
}
```

## HIR

HIR 禁止出现：

- Vue2 helper：`_c`、`_v`、`_s`、`_l`、`_f`。
- Vue3 helper：`_createElementVNode`、`_openBlock`、`_renderList`。
- patch flag。
- hoist/cache index。
- SSR `_push`。
- exact emitter whitespace。

HIR 不包含 `Call` 和 `Helper`。表达式调用属于 JS AST，runtime helper 调用属于 MIR。

`Vue3DomRoot.imports` 是 DOM target 的 module asset import 载荷。DOM/SFC transform 先把 asset URL import payload 放在 public `Vue3Root.imports`；DOM lowering 只能从 public root payload 投影到 `Vue3DomRoot.imports`，不能回扫 element attrs 重新发现 asset URL。Standalone DOM MIR codegen 在 module 模式从该 root payload 输出 deterministic `_imports_n` imports；HIR 不保存这些 bundler/codegen-only import 数据。

`MirChildren::Slots` 是 Vue 3 DOM target 的 component slot object 载荷。稳定 slot 直接记录为 `Vue3DomSlot`，slot params 必须进入 `JsAstStore` 并以 `JsPatternId` 引用，slot body 只保存同一 `Vue3DomMir` 文档中的 child node IDs。动态 slot name、slot `v-if` / `v-else-if` / `v-else`、slot `v-for` 必须记录到 `dynamic_slots`，由 DOM MIR codegen 输出 `_createSlots`、`_renderList`、动态 slot object 和 `DYNAMIC_SLOTS` patch flag。`Vue3DomConditionalSlot.alternate` 保存相邻 `v-else-if` / `v-else` 分支，codegen 不允许从 `Vue3Ast` 重新扫描兄弟节点来恢复分支链。forwarded slot 必须记录为 `Vue3SlotFlag::Forwarded`，由 DOM MIR codegen 输出 `_: 3`；codegen 不允许从 `Vue3Ast` 重新推导 slot object 或 slot flag。

`Vue3RenderSlot` 是 DOM target 的 `<slot>` outlet 载荷。静态/动态 outlet name 必须保存到 `Vue3DomSlotName`；非 `name` props 必须保存到 `Vue3DomProps`；fallback children 只保存同一 `Vue3DomMir` 文档中的 child node IDs。DOM MIR codegen 必须从该载荷输出 `_renderSlot(...)` 的 name、props 和 fallback 函数，不允许从 `Vue3Ast` 回读 `<slot>` 属性或 children。

`Vue3DomContent` 是 DOM target 的 native/component content override 载荷。`v-html` 必须保存为 `Html { expression }` 并作为 source-ordered `Vue3DomPropSegment::Content` 输出 `innerHTML` prop；`v-text` 必须保存为 `Text { expression }` 并输出 `textContent` prop，动态表达式由 DOM MIR codegen 包 `_toDisplayString(...)`，静态/缺失表达式保持直接值或空字符串。lowering 遇到 content override 时必须把 `Vue3VNodeCall.children` 置为 `MirChildren::None`，不能继续降低原 children；`innerHTML` / `textContent` 必须加入 `dynamic_props` 并触发 `PROPS` patch flag。codegen 不能回读 `Vue3Ast` 来恢复 directive 顺序、原 children 或文本转换规则。

`Vue3VNodeCall.v_show` 是 DOM target 的 native `v-show` 载荷。HIR 可保留 source directive use，但 DOM lowering 必须把 `v-show` 表达式投影到 `v_show`，并从通用 `directives` 中移除 `show`；`directives` 只保存自定义 runtime directives。DOM MIR codegen 必须从 `v_show` 输出 `_withDirectives(..., [[_vShow, expression], ...])`、`vShow` helper 和 runtime directive `NEED_PATCH`，不能通过 `_resolveDirective("show")` 或从 `Vue3Ast` / `Vue3DomDirective` 重新识别 `show`。

DOM `<Transition>` 是 DOM target 的内置组件行为。DOM parser/lowering 必须把 `Transition` / `transition`、`TransitionGroup` / `transition-group` 识别为 runtime-helper component tag，而不是普通 component asset；DOM compile / bridge 入口必须继承这些 DOM built-in 默认值。`Transition` 的唯一可见 child 若携带 native `v-show`，DOM lowering 必须把 `persisted` 作为 source-order 末尾的 `Vue3DomPropSegment::StaticAttr` 注入到 `Vue3VNodeCall.props`，以保留 object `v-bind` overwrite 语义。该注入是 DOM target payload 行为，不能写入 HIR 或依赖 codegen 从 `Vue3Ast` 重新扫描 children。`Transition` 多 child 诊断属于 Rust DOM transform 语义：transform 必须忽略 comment / ASCII HTML whitespace，保留 NBSP 为可见 child，把相邻 `v-if` / `v-else-if` / `v-else` 当作一个逻辑 child，并对多个可见 child、single child `v-for`、空 `template v-if` branch 等场景报告官方 DOM error 63；该诊断不能放入 alias shim。

DOM/SSR asset URL transform 是 DOM/SFC/SSR compile transform 行为，不是 AST/HIR 通用语义。显式 `transformAssetUrls: { base }` 的静态 URL 重写可以在 Rust asset transform 中直接改写静态 attr 值：默认 asset tags 覆盖 `video[src|poster]`、`source[src]`、`img[src]`、`image[xlink:href|href]`、`use[xlink:href|href]`，并且 `img/source srcset` 作为独立 transform 处理。Rust transform 现在覆盖两段语义：有显式 `base` 且 URL 以 `.` 开头时直接改写静态 attr/srcset；module/SFC/SSR codegen 模式下，其他可处理 URL 会注册到 `Vue3Root.imports` 并把 attr/srcset 转成静态 `v-bind` import 表达式。DOM exact emitter 输出 deterministic `_imports_n` module imports，并把这些可字符串化 import binding 排除出运行时 dynamic props / `PROPS` patch flag；public SSR compile 在存在 asset imports 时降低到 `Vue3SsrMir`，由 standalone SSR MIR codegen 从 `Vue3SsrRoot.imports` 输出 imports 和 `_ssrRenderAttr(...)`。该 payload 属于 Vue3 public RootNode / target codegen 数据，不进入 HIR；DOM target lowering 已把它投影到 `Vue3DomRoot.imports`，SSR target lowering 也已把它投影到 `Vue3SsrRoot.imports`。生成的静态参数 asset import `v-bind` 可作为 DOM target/codegen 的 stringifiable static prop 参与 DOM MIR conservative hoist 和 exact emitter root static cache；Rust exact emitter 现在有一个由 `Vue3CompilerOptions.stringify_static` / DOM `transformHoist` sentinel 启用的保守 `stringifyStatic` 切片，只在 root cached child array 中对纯静态 HTML element/text chunk 按官方阈值输出 `_createStaticVNode(...)`。该切片是 codegen 行为，不把 static HTML、cache index、helper 或 transformHoist 状态写入 HIR/MIR；完整官方 `stringifyStatic` parity 仍是后续工作，包括 constant dynamic bindings、`v-html` / `v-text`、scoped attrs、namespace、DOM placement edge cases 和 asset-import 字符串拼接，不能通过 alias shim 或从 `Vue3Ast` 回扫伪造。root-absolute 仍只有 `includeAbsolute` 时处理；external/data/bare `#` 和非 resource hash-only SVG fragment 继续保持不变。

`Vue3DomModel` 是 DOM target 的 native `v-model` 载荷。input / textarea / select / custom element 的 runtime directive kind 必须在 lowering 阶段保存为 `Text`、`Radio`、`Checkbox`、`Select` 或 `Dynamic`，表达式保存为 `JsExprId`，`.trim` / `.number` / `.lazy` 等修饰符保存在 `modifiers`。`Vue3DomPropSegment::Model` 作为 source-ordered prop segment 输出 `onUpdate:modelValue` 赋值 handler，object `v-bind` 前后顺序必须保留；`Vue3VNodeCall.models` 由 DOM MIR codegen 输出 `_withDirectives(..., [[_vModelText|_vModelRadio|_vModelCheckbox|_vModelSelect|_vModelDynamic, value, void 0, modifiers]])`。DOM codegen 不能从 `Vue3Ast` 重新判断 input type、dynamic `v-bind` 或 modifiers，也不能把 runtime helper 写入 HIR。

`Vue3DomEvent` 是 DOM target 的 native `v-on` 载荷。`runtime_modifiers` 保存需要 `_withModifiers` 的 `.stop` / `.prevent` / `.self` / system / mouse modifiers；`key_modifiers` 保存需要 `_withKeys` 的键盘 modifiers；`option_modifiers` 保存 `.passive` / `.once` / `.capture` 并由 DOM MIR codegen 追加到事件 prop 名；`click_event` 保存 `.right` / `.middle` 对 `click` 的 DOM 事件名重写。HIR 只保留原始 directive modifiers 作为共享语义，以上分类和运行时 helper 决策只能在 `Vue3DomMir` 中出现。DOM MIR codegen 必须从这些字段输出 `_withModifiers`、`_withKeys`、事件 option postfix 和 click 重写，不能从 `Vue3Ast` 或 `HirEvent.modifiers` 重新分类。

`Vue3DomBinding` 是 DOM target 的 native `v-bind` 载荷。HIR 的 `HirBinding.modifiers` 只保存 source directive modifiers；DOM lowering 必须把 `.camel`、`.prop`、`.attr` 投影为 `camel` / `force_prop` / `force_attr` target flags。DOM MIR codegen 必须从这些 flags 输出静态 key camelize、动态 key `_camelize(...)`、`.` / `^` prop key prefix 和 `NEED_HYDRATION` 相关 prop payload，不能从 `Vue3Ast` 重新读取 directive modifiers，也不能把 `_camelize` helper 或 DOM prop/attr prefix 决策写入 HIR。

`Vue3ForMir` 是 DOM target 的 `v-for` 载荷。`source`、`value_alias`、`key_alias`、`index_alias` 都必须来自 `JsAstStore`；`:key` / `key` 必须记录到 `key`，用于 keyed fragment 与 `v-memo` cache guard；`v-for` 上的 `v-memo` 必须记录为 `Vue3ForMemo`，由 DOM MIR codegen 输出 `_renderList(source, (..., _cached) => ...)`、`_isMemoSame` guard、`_item.memo` 和 `_cache` 参数。非 `v-for` `v-memo` 继续使用 `Vue3Memo` wrapper；HIR 不保存 cache index 或 memo runtime helper。

`Vue3DomEvent.cache` 是 DOM target 的 `cacheHandlers` 载荷。cache slot 只允许在 `Vue3DomMir` 中分配，HIR 的 `HirEvent` 仍只表达事件语义和 `JsStmtId` handler。DOM MIR codegen 必须从 `Vue3DomEventCache.index` 输出 `_cache[n] || (_cache[n] = handler)`，不能从 AST 或 compiler options 重新推导缓存状态。

`Vue3DomMirKind::Hoisted { index }` 是 DOM target 的 static hoist wrapper。wrapper child 继续保存在同一个 `Vue3DomMir` 文档中；DOM MIR codegen 必须从 wrapper child 渲染 `const _hoisted_{index} = ...`，普通渲染路径只输出 `_hoisted_{index}` 引用。hoist declaration 不能从 `Vue3Ast` 重新扫描静态节点，也不能把 hoist helper/runtime call 写入 HIR。

Standalone DOM MIR codegen 的 prefix identifier rewrite 是 codegen 行为，不属于 HIR 语义。`JsAstStore` 继续保存原始 expression / statement / pattern source；`generate_vue3_dom_mir` 在 render 时根据 `Vue3CompilerOptions` 重写表达式，并通过 `RenderScope` 保护 `v-for` alias、destructured alias、slot params、dynamic slot loop alias、`$event` 和 arrow handler params 等局部绑定。DOM MIR codegen 不允许为了 prefix rewrite 回读 `Vue3Ast` 或把 `_ctx` / `$setup` / `$props` 等 runtime 前缀写入 HIR / MIR payload。若 prefix/bindingMetadata rewrite 引入 `_unref`、`_isRef` 等 runtime helper，helper import 必须由 DOM MIR codegen 从最终渲染 code probe 补齐，而不是把 helper 写入 HIR/MIR expression payload。

MIR 规则：

- `vuec_codegen::CodeWriter` 的输入是 MIR。
- DOM codegen 的目标是 `Vue3DomMir`。
- SSR codegen 的目标是 `Vue3SsrMir`。
- Vue2 codegen 的目标是 `Vue2Mir`。
- SSR 不从 DOM MIR 反推。

`Vue3SsrRoot.imports` 是 SSR target 的 module asset import 载荷。DOM/SFC transform 先把 asset URL import payload 放在 public `Vue3Root.imports`；SSR lowering 只能从 public root payload 投影到 `Vue3SsrRoot.imports`，不能回扫 element attrs 重新发现 asset URL。Standalone SSR MIR codegen 在 module 模式从该 root payload 输出 deterministic `_imports_n` imports；HIR 不保存这些 bundler/codegen-only import 数据。

`Vue3SsrSlot` 是 SSR target 的 `<slot>` outlet 载荷。静态/动态 outlet name、非 `name` props、fallback children 必须直接保存在 `Vue3SsrMir` 文档和共享 `JsAstStore` id 中，不能从 DOM MIR 或 `Vue3Ast` 回推。

`Vue3SsrAttrs` 是 SSR native element 的 attrs 载荷。静态 attrs 默认继续由 opening tag `PushString` 保存；动态 `v-bind:foo` / `:class` / `:style` / `:[name]` 和 object `v-bind="obj"` 必须从 HIR props 过滤后保存到 `Vue3SsrMir`，由 SSR MIR codegen 输出 `_ssrRenderAttr(...)`、`_ssrRenderClass(...)`、`_ssrRenderStyle(...)`、`_ssrRenderDynamicAttr(...)` 和 `_ssrRenderAttrs(...)`。`v_show` 保存 SSR target 的 `v-show` 条件表达式；当 `v_show` 存在时，静态 `style` 不能直接保留在 opening tag 中，必须进入 `props` 并与动态 `:style` 和 `v-show` 的 `{ display: "none" }` 条件样式按源/SSR 优先级合并。`v_model` 保存 SSR target 的 native `v-model` 载荷：text input 输出 value attr，radio/checkbox 输出 checked boolean fragment，dynamic type 输出 `_ssrRenderDynamicModel(...)`，object `v-bind` input 输出 `_ssrGetDynamicModelProps(...)` merge payload，textarea 输出 model interpolation，select 的 descendant option 输出 selected boolean fragment。select model 必须通过 SSR lowering context 传递给 descendant `option`，并在 `Vue3SsrModelKind::SelectOption` 中作为 target data 消费；codegen 不能从 `Vue3Ast` 重新扫描 select children 或从 DOM MIR 回推。事件、object listeners 和 DOM-only props 不进入 SSR element attrs payload，codegen 不能把 `_attrs` 误当成当前元素 attrs。

`Vue3SsrContent` 是 SSR native element 的 children override 载荷。`v-html` 必须保存为 `Html { expression }` 并由 codegen 输出 raw `expression ?? ""`；`v-text` 必须保存为 `Text { expression }` 并由 codegen 输出 `_ssrInterpolate(expression)`。lowering 遇到 content override 时必须跳过原 children，并把 self-closing element 展开为 open/content/close 形式；codegen 不能为了恢复 override directive 或原 children 行为回读 `Vue3Ast`。

`Vue3SsrComponent` 是 SSR component render 载荷。组件 tag 和 props 必须来自 HIR/component lowering 后的 SSR MIR payload；standalone SSR MIR codegen 从该 payload 输出 `_ssrRenderComponent(tag, props, slots, _parent)`，不能回读 `Vue3Ast` 或 DOM MIR 来恢复 props。

`Vue3SsrFor` 是 SSR target 的 `v-for` 载荷。`source`、`value_alias`、`key_alias`、`index_alias` 都必须来自 `JsAstStore`；standalone SSR MIR codegen 从该 payload 输出 `_ssrRenderList(source, (value, key, index) => ...)`，并把所有 alias pattern 注册为局部作用域，不能只保存 value alias 或从 AST/HIR 回推 key/index。

`Vue3SsrTeleport` 是 SSR target 的 Teleport 载荷。`target` 和 `disabled` 必须来自 Teleport props lowering 后的 `MirExpr`；standalone SSR MIR codegen 从该 payload 输出 `_ssrRenderTeleport(_push, contentFn, target, disabled, _parent)`，不能把 Teleport 当普通 component 或把 target/disabled 写死。

`Vue3SsrSuspense` 是 SSR target 的 Suspense slot 载荷。稳定 `default` / `fallback` slots 以 `Vue3DomSlots` 保存 slot name、params、children 和 slot flag；standalone SSR MIR codegen 从该 payload 输出 `_ssrRenderSuspense(_push, { default, fallback, _: flag })`，不能从 AST 重新扫描 slot templates 或把 Suspense 当普通 component。

Standalone SSR MIR codegen 的输入是 `Vue3SsrMir` 和 `JsAstStore`。基础 emitter 必须从 SSR MIR 输出 `_push(...)`、`_ssrInterpolate(...)`、`_ssrRenderSlot(...)`、`_ssrRenderComponent(...)`、`_ssrRenderList(...)` 与 `v-if` statement shell，并按 module/function mode 生成 server-renderer helper preamble；codegen 不允许为了恢复 attrs、component props、slot name/props/fallback、control-flow body 或 interpolation 表达式回读 `Vue3Ast` 或 DOM MIR。


```text
HtmlTokenizer
  -> Cst
```

## 案例 1：普通元素

输入：

```vue
<div id="app" :class="foo">{{ msg }}</div>
```

CST：

```text
Element raw_tag="div"
  Attribute raw_name="id" raw_value="app"
  Attribute raw_name=":class" raw_value="foo"
  Interpolation raw="{{ msg }}" inner="msg"
```

Vue3Ast：

```text
Element tag="div" tag_type=Element
  Attribute name="id" value="app"
  Directive name="bind" raw_name=":class" arg="class" exp=JsExpr(foo)
  Interpolation exp=JsExpr(msg)
```

HIR：

```text
Element tag=Native("div")
  static_attrs: id="app"
  dynamic_bindings: class <- JsExpr(foo)
  child: Interpolation JsExpr(msg)
```

Vue3DomMir：

```text
VNodeCall
  tag: "div"
  props: { id: "app", class: JsExpr(foo) }
  children: TextInterpolation(JsExpr(msg))
  patch_flag: CLASS | TEXT
  dynamic_props: ["class"]
```

Vue3SsrMir：

```text
PushString("<div id=\"app\" class=\"")
PushInterpolated(JsExpr(foo))
PushString("\">")
PushInterpolated(JsExpr(msg))
PushString("</div>")
```

## 案例 2：v-if + v-for

输入：

```vue
<li v-for="item in list" :key="item.id" v-if="item.ok">
  {{ item.name }}
</li>
```

Vue2Ast 保留 Vue2 方言字段：

```text
Element tag="li"
  for_exp=JsExpr(list)
  alias=JsPattern(item)
  if_exp=JsExpr(item.ok)
  key=JsExpr(item.id)
```

Vue3Ast 保留 Vue3 directive：

```text
Element tag="li"
  Directive name="for" exp="item in list"
  Directive name="bind" arg="key" exp="item.id"
  Directive name="if" exp="item.ok"
```

HIR 接收方言 lowering 后的结果：

```text
For source=JsExpr(list) value_alias=JsPattern(item)
  If condition=JsExpr(item.ok)
    Element tag=Native("li") key=JsExpr(item.id)
      Interpolation JsExpr(item.name)
```

Vue3DomMir：

```text
For source=JsExpr(list) params=[item]
  If condition=JsExpr(item.ok)
    VNodeCall tag="li" key=JsExpr(item.id) patch_flag=TEXT
```

Vue2Mir：

```text
For helper=RuntimeHelper::Vue2RenderList source=JsExpr(list) alias=item
  If condition=JsExpr(item.ok)
    CreateElement helper=RuntimeHelper::Vue2CreateElement tag="li" data={ key: JsExpr(item.id) }
```

## Pass 设计

`vuec_pass::PassScheduler<N>` 保留，用于简单 flat pass。AST/HIR/MIR 文档级 pass 增加以下 trait：

```rust
pub trait DocumentPass<K> {
    fn name(&self) -> &'static str;
    fn enter(&mut self, _doc: &mut AstDocument<K>, _node: NodeId, _ctx: &mut TransformContext) {}
    fn exit(&mut self, _doc: &mut AstDocument<K>, _node: NodeId, _ctx: &mut TransformContext) {}
}
```

遍历顺序固定为 depth-first pre-order enter、post-order exit。Vue3 exit callbacks 用 pass 内部 stack 表达，不改变 scheduler 顺序。

## Public Projection

官方 API 输出不直接暴露内部 arena。每个方言提供 projection：

```rust
pub trait PublicProjection {
    type Output;
    fn project_public(&self) -> Self::Output;
}
```

规则：

- Vue2 `compile` 结果中的 `ast` 来自 `Vue2Ast::project_public()`。
- Vue3 parser/transform 测试需要的 AST JSON 来自 `Vue3Ast::project_public()`。
- projection 负责把 arena `children` 还原成官方嵌套 shape。
- projection 不允许补造内部已经丢失的信息；缺字段属于 AST 设计错误。
