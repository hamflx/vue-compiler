# Pending Decisions

- Package alias shape for the final NAPI publishing flow still needs to be finalized after the Rust surface stabilizes. It must cover Vue 2.6 and Vue 2.7 `vue-template-compiler`, Vue 2.7 `vue/compiler-sfc`, and Vue 3 `@vue/compiler-*` entries without changing official test imports.
- The first full source-test alias runner still uses a temporary JSON CLI bridge through `vuec_node_bridge`. Public API manifest, smoke, and output-contract acceptance now have a NAPI-backed official package-name path, but official source conformance still requires a migration plan for internal compiler-core/DOM/SFC/SSR imports without weakening coverage classification.
- `target/compat/rust-alias/<version-line>` remains the generated probe root for existing compatibility summaries. `target/compat/napi-alias/<version-line>` is now the version-isolated NAPI public contract probe root; future NAPI source conformance should reuse this layout and preserve official package names/subpaths.
- Option matrix rows can now be executable or explicit pending. Pending rows currently cover callback/plugin-style options and incomplete diagnostic/source-range/SFC semantics; final acceptance still requires converting these rows to executable pass rows, not deleting them or treating pending as compatible.
- Vue 3 compiler-core conformance reporting now has an initial suite-level and test-file-level execution-source model in `cargo xtask run-conformance`. A future decision remains whether to refine this to individual tests, API entries, or transform modules once Rust-backed transform/codegen migration starts.
- Decide the Rust-backed replacement path for current Vue 3 compiler-core alias runtime semantics: either expose coarse Rust bridge operations such as `transformAst` / `generateAst`, or migrate official internal transform coverage to public `baseCompile` / `baseParse` output-diff tests while keeping JS shims as non-progress adapter code.
